# Ailey & Bailey 저장·복원 이중 구조 v2

## 0. 핵심 원리

아카이브 전체를 매 새 채팅에 넣지 않는다.

- 빠른 체크포인트: 지금 이어서 공부하는 데 필요한 현재 상태
- 단원 아카이브: 완료된 단원의 상세 기록과 캔버스
- 전체 백업 JSON: 모든 폴더와 아카이브를 복구하는 재난 복구 파일

우선순위는 다음과 같다.

최신 유효 빠른 체크포인트 → 현재 단원 아카이브 → 프로젝트 채팅·파일 → 모델의 일반 기억

## 1. 명령과 UI 역할

- 저장: 빠른 체크포인트를 만들고 현재 단원 아카이브에 연결
- 복원: 빠른 체크포인트를 학습 상태로 되살림
- 단원보관: 현재 단원의 상세 기록과 캔버스를 아카이브에 확정
- 전체 백업 JSON: Ailey’s Note의 모든 폴더·아카이브·설정을 하나의 JSON으로 내보냄
- 백업 복원: 전체 백업 JSON에서 로컬 저장소를 복구
- 로컬 백업 저장: 현재 브라우저 로컬 저장소에 복구점 생성

전체 백업 복원 직후에도 모델 상태는 자동으로 안다고 가정하지 않는다. 선택한 빠른 체크포인트를 대화 입력으로 전달한 후 복원 검증을 수행한다.

## 2. 빠른 체크포인트 최소 필드

빠른 체크포인트는 다음 필드만 필수로 유지한다.

- schema_version
- packet_type
- checkpoint_id
- saved_at
- course_id
- textbook_anchor
- chat_unit_id
- current_topic
- source_range
- completed_points
- current_objective
- mastery_summary
- active_weaknesses
- unresolved_assessment
- next_action
- live_menu_bindings
- canvas_state
- archive_pointer
- integrity

packet_type은 ailey_bailey_quick_checkpoint를 사용한다.

## 3. 필드 압축 규칙

- 완료 POINT는 연속 범위로 압축
- 약점은 최대 5개만 활성 목록에 유지
- 오래된 오답 원문은 단원 아카이브로 이동
- 미해결 문제가 있을 때만 문제 전문을 유지
- 과거 점수는 최근 3회와 추세만 유지
- 전체 교육과정 목차는 빠른 체크포인트에 반복하지 않고 project_source_id로 참조
- 캔버스 HTML 전체는 넣지 않고 canvas_id, revision, snapshot_id만 저장
- 메뉴는 현재 화면의 실제 글자와 의미만 보존

## 4. 단원 아카이브 필드

단원보관은 다음을 포함한다.

- 단원 ID와 제목
- 교재 POINT·페이지 범위
- 학습한 핵심 개념
- 판례 연결도
- 확정된 강점과 약점
- 대표 오답과 교정 근거
- 점수 기록
- 최종 캔버스 snapshot_id
- 다음 단원으로 넘길 연결 개념
- 해당 단원을 다시 복습해야 하는 조건

단원 아카이브는 새 채팅마다 자동 주입하지 않는다.

## 5. 전체 백업 JSON 필드

전체 백업은 다음을 보존한다.

- 폴더 구조
- 모든 단원 아카이브
- 모든 캔버스 스냅샷 메타데이터
- 최신 빠른 체크포인트
- 프로젝트 색인
- 복원 이력
- 스키마 버전
- 무결성 해시
- 로컬 설정

전체 백업은 재난 복구용이다. 일상 복원에는 사용하지 않는다.

## 6. 복원은 zero-beat

빠른 체크포인트가 붙여 넣어지거나 선택되면 다음 순서만 수행한다.

a. JSON 구조와 integrity 확인
b. chat_unit_id와 source_range 확인
c. 미해결 평가·복습 상태 확인
d. live_menu_bindings 복원
e. canvas_id와 revision 복원
f. 같은 현재 상태를 짧게 재표시

이 턴에서는 새 설명, 새 문제, 채점, 진도 증가, 약점 재계산을 하지 않는다.

## 7. 구형 저장 패킷 호환

기존 AILEY_BAILEY_SAVE_PACKET 형식은 읽을 수 있어야 한다.

구형 전체 패킷을 불러오면 다음 두 결과로 변환한다.

- 최신 빠른 체크포인트 1개
- 상세 단원 아카이브 1개 이상

원본은 삭제하지 않고 legacy_archive로 보관한다.

## 8. 드리프트 방지

- checkpoint_id가 같은 복원을 반복해도 turn_number를 증가시키지 않음
- 명시된 숙달도와 약점을 모델 기억으로 재판정하지 않음
- source_range를 임의로 넓히지 않음
- live_menu_bindings를 새 메뉴로 바꾸지 않음
- unresolved_assessment가 있으면 문제 전문과 제출 형식을 그대로 복원
- 새로운 학습 변화가 없으면 저장-복원-저장 결과가 의미상 동일해야 함

## 9. 권장 보관 정책

- 빠른 체크포인트: 최신 1개 + 직전 3개
- 단원 아카이브: 분할 채팅 종료마다 1개
- 전체 백업 JSON: 주 1회 또는 큰 PART 종료 때
- 로컬 백업: 중요한 학습일 종료 때
- 별도 기기 저장: 전체 백업 JSON 최소 2곳

## 10. 새 채팅 첫 메시지 형식

다음 취지만 전달한다.

“아래 빠른 체크포인트를 현재 학습 상태로 복원만 해. 진도, 약점, 미해결 문제, 메뉴 의미를 바꾸지 말고 복원 결과 네 항목만 확인해. 새 수업은 시작하지 마.”

그 아래에 최신 빠른 체크포인트를 붙인다.
