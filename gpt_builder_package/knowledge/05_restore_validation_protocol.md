# Ailey’s Note 모델 상태 복원 검증 프로토콜

## 목적

화면의 아카이브 카드와 캔버스만 돌아온 것인지, GPT가 학습 상태까지 실제로 전달받았는지 구분한다.

## 준비

검증용 단원 하나를 선택하고 다음 정보를 기록한다.

- 교재 POINT·페이지
- 현재 단원
- 활성 약점 2개
- 미해결 문제 1개
- 다음 학습 행동
- 현재 메뉴 글자와 의미
- canvas_id와 revision
- checkpoint_id

검증 전 전체 백업 JSON과 빠른 체크포인트를 각각 저장한다.

## 시험 A: 같은 채팅의 화면 복원

a. Ailey’s Note에서 다른 아카이브를 연다.
b. 원래 아카이브로 돌아온다.
c. 다음 질문을 보낸다.

“현재 범위, 활성 약점, 미해결 문제, 다음 행동을 말해. 새 학습은 시작하지 마.”

판정:

- 네 항목이 모두 일치: 같은 채팅 안의 상태 연결 성공
- 화면만 일치하고 답변이 틀림: UI 복원만 성공
- 메뉴 또는 문제 번호가 바뀜: 상태 일부만 복원

## 시험 B: 새 채팅의 빠른 복원

a. 같은 헌법 프로젝트 안에서 새 일반 채팅을 만든다.
b. 첫 메시지 후 Ailey & Bailey GPT를 호출한다.
c. 빠른 체크포인트만 전달한다.
d. 다음 여덟 항목을 확인한다.

- chat_unit_id
- source_range
- current_topic
- active_weaknesses
- unresolved_assessment
- next_action
- live_menu_bindings
- canvas revision

여덟 항목이 모두 일치해야 통과다.

## 시험 C: 미해결 문제 정밀 복원

저장 직전에 OX 또는 객관식 문제 한 세트를 제출하지 않은 상태로 둔다.

복원 후 다음이 정확해야 한다.

- 문제 제목
- 문제 번호
- 지문
- 선택지 또는 OX 문장
- 제출 형식
- 아직 채점되지 않았다는 상태

문제 전문을 사용자가 다시 설명해야 한다면 실패다.

## 시험 D: 메뉴 결합 검증

저장 직전 나침반의 각 글자 의미를 기록한다.

복원 후 같은 글자를 입력해 본다.

- 원래 의미대로 작동: 통과
- 오래된 메뉴 또는 기본 메뉴로 이동: navigation_state 전달 실패
- 복원만 했는데 메뉴가 새로 생성됨: zero-beat 규칙 위반

## 시험 E: 캔버스 revision 검증

a. .cc로 revision 1 생성
b. 학습 후 .cu로 revision 2 생성
c. 저장 후 새 채팅에서 복원
d. .cv 실행

판정:

- revision 2가 열림: 통과
- revision 1이 열림: 최신 포인터 갱신 실패
- 새 전체 캔버스가 생성됨: view와 create 구분 실패
- 캔버스는 맞지만 약점이 다름: 화면 상태와 학습 상태가 분리됨

## 시험 F: 저장-복원-재저장 드리프트

a. 빠른 체크포인트 저장
b. 새 채팅 복원
c. 아무 학습도 하지 않고 다시 저장
d. 두 체크포인트 비교

다음 필드는 같아야 한다.

- 완료 POINT
- 숙달 요약
- 활성 약점
- 미해결 평가
- 다음 행동
- 메뉴 의미
- canvas_id와 revision

saved_at과 새 checkpoint_id만 달라질 수 있다.

## 점수표

- A 15점
- B 25점
- C 20점
- D 15점
- E 15점
- F 10점

90∼100점: 모델 상태까지 안정적으로 복원
75∼89점: 일부 필드 전달 누락
50∼74점: UI 중심 복원
49점 이하: 백업은 되지만 학습 연속성은 보장되지 않음

## 실패 원인별 수정

### 화면만 복원되는 경우

복원 버튼이 localStorage를 갱신한 뒤 빠른 체크포인트를 실제 사용자 메시지 또는 GPT Action 결과로 모델에 전달하도록 수정한다.

### 미해결 문제가 사라지는 경우

빠른 체크포인트의 unresolved_assessment에 문제 전문과 제출 형식을 보존한다.

### 메뉴가 바뀌는 경우

live_menu_bindings를 저장하고 복원 턴에서 새 나침반 생성을 금지한다.

### 캔버스가 과거 revision으로 돌아가는 경우

snapshot_id, canvas_id, revision을 하나의 원자적 트랜잭션으로 저장한다.

### 저장할수록 상태가 변하는 경우

복원·표시·검증 턴을 학습 턴에서 제외하고 mastery와 progress 재계산을 금지한다.
